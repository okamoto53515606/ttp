Tera Term の接続管理を、属人化させない。

認証情報を、ファイルに残さない。
接続先は GUI の一覧から選ぶだけ。マクロは 1 本を全員で共有します。

最新版をダウンロード できることを見る

zip を解凍するだけ／インストール不要／レジストリ不使用／Tera Term 4・5 対応

  • マクロは 1 本 接続先ごとに .ttl を作らない。共有するのは connect.ttl だけ。
  • AES-256 で暗号化 パスワード・鍵・AWS キーは、マスターパスワード由来の鍵で保護。
  • ログは自動 接続のたびにタイムスタンプ付きログを生成。取り忘れがない。

いま、こんな運用になっていませんか

01

共有フォルダの .ttl が、認証情報の山になっている

マクロの書き方として紹介されるサンプルは、ほぼすべて PASSWORD = '...' の平文です。接続先が増えるほど、パスワードが書かれたファイルが増えていきます。

02

マクロを書ける人が、一人しかいない

接続先を足すたびに、その人へ依頼する。異動や退職で、誰も触れなくなる。手順書もマクロも、属人化したまま残ります。

03

誰がいつ入ったか、説明できない

「ログを取っておいて」と決めても、実際には取り忘れる。監査や障害対応のときに、作業履歴が出てきません。

TTP がやること

接続先の管理と、認証情報の扱いを分離します。マクロを書く人がいなくても、全員が同じ手順で接続できる状態をつくります。

よくある形 接続先ごとの .ttl 
; 自動ログインサンプル.ttl
HOSTADDR = '192.168.1.10'
USERNAME = 'admin'
PASSWORD = 'P@ssw0rd'   ← 平文で残る

COMMAND = HOSTADDR
strconcat COMMAND ':22 /ssh /2 /auth=password'
strconcat COMMAND ' /user='
strconcat COMMAND USERNAME
strconcat COMMAND ' /passwd='
strconcat COMMAND PASSWORD
connect COMMAND
接続先が 20 あれば、パスワード入りの .ttl が 20 個。
TTP connect.ttl 1 本 
; connect.ttl （全接続先で共通）
getenv 'TT_TTL_HOST'   myhost
getenv 'TT_TTL_PORT'   myport
getenv 'TT_TTL_USER'   myuser
getenv 'TT_TTL_PASSWD' mypasswd   ← 実行時だけ

myconnectparam = ''
strconcat myconnectparam myhost
strconcat myconnectparam ':'
strconcat myconnectparam myport
strconcat myconnectparam ' /ssh /2 /auth=password'
strconcat myconnectparam ' /user='
strconcat myconnectparam myuser
strconcat myconnectparam ' /passwd='
strconcat myconnectparam mypasswd
connect myconnectparam
接続先が 20 でも、マクロは 1 本。認証情報はファイルに残りません。

できること

01

接続先は一覧で管理

名前・ホスト・ポート・認証方式・ユーザを一覧表示。列で並べ替え、複製、削除ができます。選んでダブルクリックすれば接続します。

02

マクロは 1 本を共有

同梱の connect.ttl に接続情報を環境変数で渡します。接続先が増えても .ttl は増えません。

03

認証情報は暗号化して保持

AES-256 (Fernet) で暗号化。鍵導出は PBKDF2 の 480,000 回反復。マスターパスワード自体は保存しません。

04

マクロに認証情報を書かない

パスワードは子プロセスの環境変数として渡します。共有フォルダに .ttl が置かれていても、そこにパスワードはありません。

05

ログは自動で残る

接続のたびに 日時_接続名.log を生成し、そのまま記録を開始します。保存先は設定で変更できます。

06

ポータブル

zip を解凍するだけ。レジストリも AppData も使いません。アンインストールはフォルダを削除するだけです。

このほか、踏み台を経由する多段接続、鍵ファイルの暗号化保存、ttpmacro.exe の自動検出（Tera Term 4 / 5）に対応しています。

配布と更新について

コード署名はしていません。その代わり、依存の更新と脆弱性チェックを毎月自動で回し、その結果を GitHub に残しています。

初回だけ、警告が出ます

「詳細情報」→「実行」で起動できます。2回目以降は表示されません。コード署名証明書を使っていないためで、動作に問題があるという意味ではありません。判断材料は配布と更新の方針にまとめています。

毎月、自動で更新しています

毎月1日 03:00 に GitHub Actions が依存を最新化し、スモークチェックと pip-audit による脆弱性検査を通したうえで、新しい版を自動リリースします。検査に落ちた場合はリリースされません。

配布と更新の方針を読む

導入

  1. zip を任意のフォルダに解凍

    デスクトップや C:\Tools\ttp\ など、分かりやすい場所に置いてください。Program Files 配下は権限の問題が起きる場合があるため避けます。

  2. ttp.exe を起動し、マスターパスワードを設定

    このパスワードが接続情報を暗号化する鍵になります。忘れると復号できないため、パスワード管理のルールに沿って保管してください。

  3. ttpmacro.exe を確認して、接続先を登録

    Tera Term 4 / 5 を自動検出します。接続先を登録したら、一覧から選んでダブルクリックで接続できます。

初回起動時の SmartScreen について。 コード署名を付けていないため、「Windows によって PC が保護されました」と表示されることがあります。 「詳細情報」→「実行」で起動できます。2 回目以降は表示されません。 内容を確認したい場合は、GitHub のソースから uv run python build.py で自分でビルドできます。

よくある質問

Tera Term 5 で LogMeTT が使えなくなりました。代わりになりますか？

はい。Tera Term 5.0 で LogMeTT と TTLEditor はインストーラから削除され、これらはソース非公開のため復活していません。TTP は接続先を一覧で管理し、マクロを介して Tera Term に接続するツールで、LogMeTT の「接続先を選んで起動する」役割を置き換えられます。

LogMeTT からの移行もご覧ください。

TeraTerm Menu との違いは何ですか？

TeraTerm Menu は Tera Term に同梱される接続先ランチャーです。TTP は接続先の管理に加えて、認証情報を AES-256 で暗号化して保持し、マクロファイルには認証情報を書き出さず、接続ログを自動取得します。設定はレジストリではなくアプリのフォルダ内に保存するため、ポータブルに扱えます。

TeraTerm Menu との違いに詳しくまとめています。

パスワードはどこに保存されますか？

ttp フォルダ内の ttp_data に、マスターパスワードから導出した鍵で暗号化して保存します。暗号化は AES-256 (Fernet)、鍵導出は PBKDF2 の 480,000 回反復です。マスターパスワード自体は保存せず、検証用のトークンのみを保持します。

パスワードをファイルに残さない方法で、他の選択肢と比較しています。

接続先ごとにマクロファイルを作る必要がありますか？

いいえ。TTP は接続先ごとに .ttl を生成しません。同梱の connect.ttl 1 本に接続情報を環境変数で渡して起動します。接続先が増えてもマクロファイルは増えないため、どれが現役のマクロか分からなくなることがありません。

AWS CLI は必要ですか？

AWS から接続する機能（SSM / ECS Exec）を使う場合、必要なのは Session Manager プラグインだけです。AWS CLI v2 は不要です（インストール済みの場合はフォールバックとして使われます）。Tera Term マクロによる SSH 接続だけを使う場合は、AWS 関連の設定は一切不要です。

RLogin とどちらを使うべきですか？

タブ管理や画面分割、SFTP までターミナル内で完結させたい場合は RLogin が向いています。Tera Term のマクロやシリアル接続をそのまま使い続けたい場合は、ターミナルを乗り換えずに接続管理だけを整える TTP が向いています。

RLogin との使い分けもご覧ください。

初回起動時に「Windows によって PC が保護されました」と表示されます。大丈夫ですか？

コード署名証明書を使っていないため表示されます。「詳細情報」→「実行」で起動でき、2回目以降は表示されません。
